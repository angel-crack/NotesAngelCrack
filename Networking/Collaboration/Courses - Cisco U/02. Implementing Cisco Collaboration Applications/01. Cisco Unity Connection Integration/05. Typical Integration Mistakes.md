There are three main areas where you can experience problems that are related to integration between Cisco Unity Connection and the phone system: calls to Cisco Unity Connection are failing, voicemail ports are failing to register, and MWI problems.

| Calls to Cisco Unity Connection are failing       | Ports are failing to register | MWI problems       |
| --------------------------------------------------------------------------------- | ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| - Phone system settings do not match.<br>- Routing rules are working incorrectly. | - Device name prefix issues   | - MWI is not enabled for voicemail ports.<br>- Voicemail ports for MWI are too busy.<br>- Incorrect MWI extensions.<br>- MWI is disabled for the user.<br>- Incorrect phone system.<br>- CSS issues<br>- Dial plan overlap |

When the phone system settings in Cisco Unity Connection Administration do not match the type of phone system to which Cisco Unity Connection is connected, Cisco Unity Connection may not answer calls. To troubleshoot this issue, you can use the Check Telephony Configuration test. To use this test, you would go to Cisco Unity Connection Administration and find the Related Links box in the upper right corner of any Telephony Integrations page. You would then choose Check Telephony Configuration and click Go. If the test is not successful, the Task Execution Results displays one or more messages with troubleshooting steps. After correcting the problems, run the test again.

If routing rules are not working correctly, Cisco Unity Connection may not answer some calls. By default, Cisco Unity Connection does not reject any calls. If routing rules have been changed, Cisco Unity Connection may have been unintentionally programmed to reject some internal or external calls. Another reason for this problem could be that the phone system is programmed to send calls to a voice messaging port on Cisco Unity Connection that is not configured to answer calls. You might also find that voice messaging ports are disabled.

You can experience problems if another port group on the Cisco Unity Connection server or another Cisco Unity Connection server uses the same device name prefix to connect ports to the Cisco Unified Communications Manager server. You may find that Cisco Unity Connection voice messaging ports do not register with Cisco Unified Communications Manager in an SCCP integration. Another possible issue is that the Cisco Unity Connection ports repeatedly disconnect from Cisco Unified CM in an SCCP integration.

The MWI is a lamp, flashing LCD panel, or special dial tone on user phones that lets users know that a voice message is waiting. The type of indicator depends on the phone system and the user phones. When a message for a user arrives on the Cisco Unity Connection message store, Cisco Unity Connection notifies the phone system to turn on an MWI on the phone for that user. If there are integration problems with the phone system, your MWI might exhibit these problems:

- **MWI does not turn on or off:** Typical reasons for this problem are as follows:
    
    1. There are no voice messaging ports for the phone system integration that are assigned to send MWI requests.
    2. Voice messaging ports that are assigned to send MWI requests are not enabled.
    3. An inadequate number of voice messaging ports for the phone system integration are assigned to send MWI requests. The ports may be too busy to dial out immediately to turn MWIs on and off.
    4. Port groups for the phone system integration disable MWIs.
    5. (For SCCP integrations only) The MWI On Extension field and the MWI Off Extension field settings are incorrect.
    6. MWIs for the phone system are forced off. This situation occurs when the Force All MWIs Off for This Phone System check box is checked.
    7. MWI is disabled for the user.
    8. An incorrect phone system is assigned to the MWI for the user.
    9. (For SCCP integrations only) The extensions that turn MWIs on and off are not in the CSS that contains the phones and voicemail ports.
    10. (For SCCP integrations only) The dial plan overlaps the MWI extensions.

- **MWIs turn on but do not turn off:** This problem applies to PIMG and TIMG integration and the cause may be port memory. For Avaya, Rolm, and Siemens Hicom phone system integrations, Cisco Unity Connection must use the same port to turn off an MWI that was used to turn on the MWI. When Cisco Unity Connection is integrated with one of these phone systems and uses a different port to turn off an MWI, the MWI request to turn off the MWI fails.
    
- **Delay for MWIs to turn on or off:** If MWIs are being synchronized for a phone system integration, this synchronization may result in delayed MWIs for messages. This situation is due to the additional MWI requests that are being processed. Another reason for this problem could be an insufficient number of ports that are assigned to process MWI requests.
