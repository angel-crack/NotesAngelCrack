## SIP Federation Deployments

IM and Presence Service supports SIP federation with Microsoft systems, such as Skype for Business on-premises or Microsoft Office 365.

![[Pasted image 20250101104118.png]]

IM and Presence Service interdomain federation with Microsoft Lync or Skype for Business Server provides basic presence (available, away, busy, offline) and point-to-point instant messaging. Rich presence capability (On the Phone, In a Meeting, On Vacation, and so on), and advanced instant messaging features, are not supported.

The following diagram demonstrates both a business-to-business federation and a single-enterprise network federation for a Skype for Business server.

![[Pasted image 20250101104126.png]]

- With business-to-business (B2B) federation, communication occurs between the IM and Presence Service (on the left of the figure) and a remote Skype for Business server that is located in another company's network (on the right side of the figure). The integration requires communications to cross the company firewall. So, in addition to a Cisco Expressway-C that is deployed within the enterprise network, you must deploy Cisco Expressway-E within the DMZ of the firewall.
    
- With a single-enterprise network, an on-premises Skype for Business server is located in the company network, but in a separate domain. In the diagram, the Skype for Business server is within the internal firewall. This integration requires Cisco Expressway-C, but does not require Expressway-E because communication does not need to cross the firewall.
    

Cisco Expressway provides an alternative to the Cisco ASA TLS Proxy for interdomain SIP federation that was used in the past. You may reuse existing Cisco Expressways that are already used for business-to-business communications, or a dedicated Expressway pair could also be deployed specifically for federation.

In an IM and Presence Service deployment with an intercluster and a multinode cluster, when an external domain initiates a new session, Cisco Expressways route all messages to an IM and Presence Service node that is designated for routing. If the IM and Presence Service routing node does not host the recipient user, it routes the message through intercluster communication to the correct IM and Presence Service node within the cluster. The system routes all responses that are associated with this request through the IM and Presence Service routing node.

An IM and Presence Service node can initiate a message to an external domain through a Cisco Expressway. In Microsoft Skype for Business, when the external domain replies to these messages, the replies are sent directly back to the IM and Presence Service node that initiated the message through the Cisco Expressway.

The IM and Presence Service uses the standard SIP (RFC 3261) to federate with the following applications:

- Microsoft Office 365 (business-to-business)
    
- Microsoft Skype for Business 2015, Standard Edition and Enterprise Edition (business-to-business)
    
- Microsoft Lync 2010 and 2013, Standard Edition and Enterprise Edition
    
- Microsoft Office Communications Server Release 2 (OCS R2), OCS 2007

## XMPP Federation Deployments

You can use XMPP federation to integrate with another IM and Presence Service cluster in another domain over the internet. It is possible to configure external XMPP federation from an on-premises IM and Presence Service server through Cisco Expressway or through the IM and Presence Service. The preferred method for deploying external XMPP federation is through Cisco Expressway. Cisco Expressway enables users who are registered with the IM and Presence Service to communicate via Cisco Expressway-E with users from a different XMPP deployment.

Cisco Expressway-E supports XMPP federation with the following entities:

- Cisco Unified Communications Manager IM and Presence Service Release 9.1 or later
    
- Cisco WebEx Connect Release 6.x
    
- XMPP standards-compliant servers
    
![[Pasted image 20250101104205.png]]

The following diagram shows how XMPP messages are routed from an on-premises IM and Presence Service server via the Cisco Expressway-C and Expressway-E Collaboration Edge solution to the federated XMPP server. It also shows the ports and connections that are used as the messages traverse DMZ firewalls. Note that the "a.com" organization is using an Expressway federation model (left side of picture), while the "b.com" organization (right side of picture) is using an IM and Presence Service in the DMZ federation model.

![[Pasted image 20250101104217.png]]

If you enable XMPP federation on Cisco Expressway, it starts to manage all XMPP communications between the federated domains. This communication uses port 5269 to communicate with the federated domains. Internal XMPP traffic between Extensible Communications Platform (XCP) routers on Cisco Expressway-E, Expressway-C, and IM and Presence Service runs on port 7400.

If you deploy external XMPP federation through Cisco Expressway, do not activate the Cisco XCP XMPP federation Connection Manager feature service on IM and Presence Service. Also make sure that Interdomain XMPP federation has been disabled on the IM and Presence Service.
