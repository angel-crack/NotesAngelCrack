## Cisco Unified Communications Manager and IM and Presence Service Clusters

Intracluster traffic participates at a low level between IM and Presence Service and Cisco Unified Communications Manager and between the IM and Presence Service publisher and subscriber nodes.

![[Pasted image 20250101102359.png]]

Starting with Version 10.x, the Cisco Unified Communications Manager IM and Presence Service node is a subscriber server in the Cisco Unified Communications Manager cluster. However, the IM and Presence Service cluster still has its own publisher and subscriber servers within the subcluster concept for high availability. The two clusters require configuration so that Cisco Jabber can register and work properly.

The IM and Presence Service publisher node uses and builds on the database of the Cisco Unified Communications Manager publisher by sharing the end-user and device information. An IM and Presence Service cluster supports only a single Cisco Unified Communications Manager cluster. Therefore, all presence users of the IM and Presence Service cluster must be defined within the same Cisco Unified Communications Manager cluster.

The two clusters share a common host file and have a strong trust relationship using IP tables.

The IM and Presence Service publisher node communicates directly with the Cisco Unified Communications Manager publisher via the AXL API using the SOAP interface.

## IM and Presence Service High Availability

IM and Presence Service relies on the subcluster to provide high availability for Cisco Jabber clients.

![[Pasted image 20250101102414.png]]

The IM and Presence Service cluster consists of a maximum of six servers, which can be configured into multiple subclusters with a maximum of three subclusters for high availability. A subcluster contains a maximum of two servers and allows users who are associated with one server of the subcluster to use the other server in the subcluster if a failover event occurs. IM and Presence Service does not provide failover between subclusters.

When deploying an IM and Presence Service cluster for high availability, you must consider the maximum number of users per server to avoid oversubscribing a server within the sub-cluster if there is a failover.

You can achieve high availability using two setups: active/active or active/standby. You can set up the nodes in a presence redundancy group to work in balanced mode, which provides redundant high availability with automatic user load balancing and user failover if one of the nodes fails. In an active/standby setup, the standby node takes over for the active node if the active node fails.

![[Pasted image 20250101103007.png]]

The IM and Presence Service cluster supports a maximum of 75,000 users in full unified communications mode, across three single IM and Presence Service nodes deployed with the 25,000-user virtual machine (VM) configuration template but with no high availability.

A high-availability deployment for 75,000 users would require three IM and Presence Service subcluster pairs that are deployed with the 25,000-user VM configuration template option.
