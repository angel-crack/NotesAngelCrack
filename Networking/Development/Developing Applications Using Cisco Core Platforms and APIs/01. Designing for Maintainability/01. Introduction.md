The lifecycle of software applications tends to be dynamic and changes are to be expected. Applications might be created in a development environment, then deployed in the production environment, then some change requests for specific functionality might be added, the underlying infrastructure could change, and so on.

It is always important to consider how easy it would be to work with a particular application in the long term. Application success can depend on how well it can adapt to ever-changing customer and market demands. Working on poorly designed code can be difficult, with tasks taking up more time than they should. On the other hand, well-designed applications can be easy to change and are able to add business value much quicker.

Creating well-designed code begins in the design phase, where it is important to design your applications with maintainability in mind. Software maintainability deals with aspects such as how easy your applications are to repair, update, fix, or change in any way.

The maintainability of software is often thought of as a scale that tells you how difficult an application or a piece of code is to understand, maintain, repair, and enhance. With long-running applications, the cost of maintenance can often amount to half or more of the project-related expenses, which is why it is important to make software as maintainable as you can in both design and implementation.
